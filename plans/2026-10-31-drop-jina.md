# Plan: remove Jina, fetch pages in the background script

Version target: **0.2.0**. Status: implemented and tested on desktop Chromium
(2026-10-31). Not yet tested on Orion iOS (section 3).

## 1. Goal

- Remove Jina Reader and the Jina key.
- The extension fetches the article itself, in its background context.
- The content script extracts the article text with **Defuddle**.
- The extension works on **Orion iOS** and on desktop Chrome.
- The user enters one key only: the OpenRouter key.

Out of scope: removing the OpenRouter key (that needs the OpenRouter sign-in flow, a separate task).

## 2. Design

```
HN page (content script)                     Background (scripts / service_worker)
------------------------                     ------------------------------------
click (+)
  -> sendMessage {type:'hnsum:fetch', url, fresh}  ->  check URL (http/https, not private)
                                                       fetch(url, no cookies, 20 s limit)
                                                       read max 3 MB, decode charset
  <- {ok, finalUrl, contentType, html}             <-
DOMParser -> Defuddle.parse() -> plain text
fetch OpenRouter (as today) -> summary -> panel + cache
```

Decisions:

| Decision | Choice | Reason |
|---|---|---|
| Where to fetch | Background context | A content script cannot read other sites. 4 of 4 sites I checked send no CORS header. |
| Background type | `scripts` + `service_worker`, same file, no `import` | Chrome 121+ uses `service_worker`. Orion and Firefox use `scripts` (Orion issue #13760). The old module worker probably did not load on Orion iOS. |
| What the background does | Fetch only. Return HTML text. | A service worker has no `DOMParser`. Short jobs avoid the "popup closed" bug (Orion #8179). |
| Where to extract | Content script | It has a DOM on all browsers. |
| Extractor | Defuddle 0.19.6, file `dist/index.js` | One file, no build step. Has extractors for HN, GitHub, Substack, NYTimes, Wikipedia, LWN, Medium, Reddit. Retries with less removal when the result is short. |
| OpenRouter call | Stays in the content script | It works today on Orion. Do not move it. |
| Reply method | `sendResponse` + `return true` | Works in all browsers. Chrome supports a returned Promise only from Chrome 146 (gradual rollout). |

Defuddle notes (checked in the 0.19.6 package):

- The global name is `Defuddle`. It is the class. Use `new Defuddle(doc, opts).parse()`.
- Use `parse()` only, never `parseAsync()`. Only the async path calls third-party services (YouTube, fxtwitter, bilibili, c2).
- Always give `url: finalUrl`. A `DOMParser` document has the URL of the HN page. Without the option, Defuddle selects the HN extractor for every article.
- A `DOMParser` document has no window. Defuddle handles this (`getComputedStyle` returns `null`).
- Size is 340 KB. Readability 0.6.0 is 90 KB and is the alternative if the size causes problems on iOS. The change is one call.

## 3. Test on Orion iOS

Change from the first plan: there is no separate test extension. The extension
has both reply methods:

- A: `sendResponse` + `return true` (used first).
- B: the background sends the result as a new message with
  `chrome.tabs.sendMessage(sender.tab.id, …)`. The content script asks for B
  only when the reply of A is empty. The console then shows
  `normal reply failed, trying tab message`.

Install 0.2.0 on Orion iOS (update Orion first) and run each case:

| # | Case | Expected |
|---|---|---|
| 1 | Popup never opened since Orion start | HTML arrives |
| 2 | Popup opened, then closed | HTML arrives |
| 3 | Orion in background for 10 min, then back | HTML arrives, or the "not running" message shows |
| 4 | 2 MB page | HTML arrives (message size is OK) |
| 5 | `http://` page | HTML arrives |
| 6 | Reply method A against method B | Record which one works |

Result rules:

- If summaries work, keep the code as it is.
- If every case shows "Extension background is not running", the background
  does not run on Orion iOS. Then use the hidden extension frame (an extension
  page in an `<iframe>` that fetches).
- If a plain `service_worker` (without `scripts`) also works on Orion iOS,
  remove `scripts` from the manifest. This removes the Chrome warning.

### 5.2 `src/background.js` (new, no imports)

Rules:

- Accept only `msg.type === 'hnsum:fetch'` and `sender.id === chrome.runtime.id`.
- Accept only `http:` and `https:` URLs.
- Refuse private hosts: `localhost`, `*.local`, `*.internal`, `127.*`, `10.*`, `192.168.*`, `172.16–31.*`, `169.254.*`, `0.*`, `[::1]`, `[fc..]`, `[fd..]`. Reason: anyone can post an HN link to `http://192.168.1.1/`. Jina fetched from its servers. Now the user's browser fetches, and the text goes to OpenRouter. Also check `res.url` after redirects. Limit: a public name that resolves to a private address is not detected (there is no DNS API).
- `fetch` with `credentials: 'omit'` (no cookies, no logged-in content) and `cache: fresh ? 'no-store' : 'default'`.
- Use an `AbortController` with a 20 s limit.
- Accept `text/html`, `application/xhtml+xml`, and `text/plain`. Refuse other types (PDF, images) with `NotHtml`.
- Read at most 3 MB from `res.body.getReader()`, then cancel. If `res.body` is missing, use `arrayBuffer()`. Cut the result to 3 MB.
- Decode the charset: use `charset=` from `Content-Type`. If it is missing, search the first 2 KB for `<meta charset>` or `http-equiv`. Use `new TextDecoder(label)`, with UTF-8 as the fallback. `res.text()` is wrong for Shift_JIS and windows-1252 pages that declare the charset only in `<meta>`.
- Always reply. Never throw.

Reply shape:

```js
{ ok: true,  finalUrl, contentType, html }
{ ok: false, name: 'BadUrl'|'Blocked'|'Http'|'NotHtml'|'Timeout'|'Network', status, raw }
```

Sketch:

```js
chrome.runtime.onMessage.addListener((msg, sender, sendResponse) => {
  if (!msg || msg.type !== 'hnsum:fetch' || sender.id !== chrome.runtime.id) return;
  fetchPage(msg.url, msg.fresh).then(sendResponse);
  return true; // keep the channel open for the async reply
});
```

### 5.3 `src/content.js` (changed)

Remove:

- `fetchReadable()` (lines 91–120) and all Jina headers.
- `jinaKey` in `loadSettings`, `configured`, the `storage.onChanged` filter, and `DISABLED_TITLE`.

Add:

1. `askBackground(msg, ms = 25000)`. Send the message and wait at most 25 s. If the reply is `undefined`, an error, or late, return `{ ok: false, name: 'NoBackground' }`. This replaces the old silent "unknown error".
   - If Phase 0 selects method B: add a `chrome.runtime.onMessage` listener for `hnsum:fetch-result`, matched with a `reqId` from `crypto.randomUUID()`.
2. `extract(html, finalUrl, contentType)`:
   - If `contentType` is `text/plain`: use the text as it is.
   - Else: `const doc = new DOMParser().parseFromString(html, 'text/html')`.
   - `const r = new Defuddle(doc, { url: finalUrl, removeImages: true, useAsync: false }).parse()`.
   - Convert `r.content` (HTML) to text with a small `htmlToText()`: put a new line after block elements, put `- ` before `li`, and remove extra blank lines.
   - If the text has fewer than 40 words, throw `NoContent`.
   - Return `{ title: r.title || doc.title, content: text }`.
3. In `doSummarize`, replace the Jina call: `askBackground` → `extract` → `summarizeText` (not changed).

A `DOMParser` document does not run scripts or load images. So parsing does not make network calls.

New error messages in `curateError` (the button title and the alert):

| name / status | Message |
|---|---|
| `NoBackground` | Extension background is not running. Open the extension popup one time, then try again. |
| `Timeout` | The page took too long to load. |
| `Network` | Network error. Check your connection. |
| `Blocked` | Links to local network addresses are not supported. |
| `BadUrl` | This link cannot be summarized. |
| `NotHtml` | This link is not a web page (for example, a PDF). |
| `Http` 401/403 | The site blocked the request. |
| `Http` 404/410 | Page not found. |
| `Http` 429 | The site limits requests. Try again later. |
| `Http` other | Could not fetch the page (HTTP n). |
| `NoContent` | No article text found on the page. |

Remove the Jina 401 and Jina 429 messages. Keep all OpenRouter messages.

HN text posts (`item?id=`) use the same path. The Defuddle HN extractor reads them.

## 7. Known losses compared with Jina

- PDFs are not summarized. A later version can add `pdf.js`.
- Pages that make their text with JavaScript give `NoContent`.
- Sites with bot checks block more often than they blocked Jina.
- Logged-in content is not available (no cookies). This is intentional.
